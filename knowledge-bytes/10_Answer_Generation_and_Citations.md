# 10 — Answer Generation and Citations

## 1. What this component does

Turns ranked evidence into a natural-language answer with validated `[n]` citations — or honestly refuses when the evidence doesn't support an answer. This is where the LLM enters the pipeline, and *only* here.

## 2. Why it exists

Retrieval finds evidence; it doesn't *answer*. Generation synthesizes, but LLMs hallucinate. This component's job is synthesis *with guardrails*: strict evidence-only prompting, citation validation, retry-then-strip, and explicit refusal paths.

## 3. Where it lives in the repository

- `src/sgrag/generation/generator.py` — `GroundedGenerator`, `answer()`, `_retrieve_all()`, `GenerationResult`
- `src/sgrag/generation/prompts.py` — `build_evidence_block()`, `build_messages()` (strict vs normal)
- `src/sgrag/generation/llm.py` — `LLMProvider` (Protocol), `GroqProvider`, `MockProvider`, `make_provider()`
- `src/sgrag/generation/citations.py` — `extract_citations()`, `validate_citations()`, `strip_invalid_citations()`
- `src/sgrag/generation/evidence.py` — `pack_evidence()`
- `src/sgrag/generation/config.py`, `models.py` — `GenConfig`, `EvidenceItem`, `GenerationResult`
- `.env`: `SGRAG_LLM_PROVIDER`, `SGRAG_LLM_MODEL`, `SGRAG_LLM_API_KEY`

## 4. Important classes/functions

- **`GroundedGenerator.answer(query)`** — the full flow: classify → (unsupported? refuse) → retrieve → (no evidence? refuse) → pack → generate → validate → (invalid? strict retry) → (still invalid? strip) → return `GenerationResult`.
- **`build_messages(query, evidence, strict=False)`** — constructs the chat messages: system prompt instructs *answer only from the provided evidence, cite as [n]*; `strict=True` adds stronger wording for the retry.
- **`GroqProvider.generate(messages, ...)`** — calls Groq (`openai/gpt-oss-120b` default); `MockProvider` returns deterministic illustrative text for offline runs.
- **`validate_citations(answer, pmids, chunk_ids)`** — extracts `[n]` markers via `extract_citations()` and checks each against the retrieved evidence set. Returns validity + list of offenders.
- **`strip_invalid_citations(answer, invalid)`** — removes hallucinated citations rather than letting them stand.

## 5. Step-by-step execution

```text
answer("What drugs are associated with breast cancer treatment?")
  → classify → entity_focused (not unsupported)
  → _retrieve_all → ranked chunks
  → pack_evidence(top 8) → EvidenceItems [1..8]
  → build_messages(query, evidence, strict=False)
       SYSTEM: "Answer ONLY from the evidence below. Cite sources as [n]..."
       USER: evidence block + question
  → llm.generate() → draft answer with [1], [3], [5]
  → validate_citations(): all in {1..8}? YES → return
  --- if NO: ---
  → build_messages(strict=True) → regenerate
  → validate again → if still invalid: strip_invalid_citations()
  → GenerationResult(answer, evidence, citations, warnings, metadata)
```

**Refusal paths:** unsupported query → `UNSUPPORTED_QUESTION_ANSWER` (before retrieval); empty evidence → `INSUFFICIENT_EVIDENCE_ANSWER` ("LLM not called" warning); retrieval failure → "literature database could not be reached"; LLM failure → "evidence was retrieved but no answer could be generated."

## 6. Data flow

`list[EvidenceItem]` (top 8) → `build_evidence_block()` (numbered text) → `build_messages()` → `llm.generate()` → `str` → `validate_citations()` → final `str` + `GenerationResult`.

## 7. How it connects to the rest of the system

`answer()` is called by `ask_pipeline()` (app.py) and `scripts/ask.py`. It owns the `HybridRetriever` (lazy via `retriever` property) and the `LLMProvider` (lazy via `llm` property). The UI renders `result.answer`, `result.evidence`, citations, and `result.warnings`.

## 8. Important design decisions

- **LLM sees only evidence:** the prompt contains the top-8 chunks, not the query's raw graph neighborhood. This bounds hallucination surface.
- **Validation, not trust:** citations are *checked* against the evidence set — the model doesn't get credit for plausible-looking `[n]`s.
- **Retry-then-strip:** one stricter retry, then remove bad citations. Never silently publish a hallucinated citation.
- **Provider-agnostic:** `LLMProvider` Protocol with Groq/OpenAI/Ollama + mock. Swapping providers is config, not code.
- **Honest refusals at four levels:** unsupported / no evidence / retrieval down / LLM down — each with a distinct, user-visible message.

## 9. Example from the actual project

*"What is RAG and how is it better than an LLM?"* → classified `UNSUPPORTED` (non-scientific) → `answer()` returns the unsupported-answer text immediately. No Neo4j query, no embedding, no LLM call. The system knows its scope and says so.

## 10. Common misunderstandings

- **"The LLM retrieves."** No — retrieval is fully done before the LLM is called; it only receives 8 evidence chunks.
- **"Citations are generated by the model freely."** They're generated *then validated* against the evidence set; invalid ones trigger retry/strip.
- **"Mock provider is the real thing."** `MockProvider` returns illustrative text for offline demos — grounded answers need a real key. The UI labels this ("Mock LLM · illustrative answers").

## 12. Natural Spoken Answers

**"How do you prevent hallucinations?"**
> "Sir, three layers. First, the prompt is strict evidence-only — the model is instructed to answer only from the eight provided chunks and cite them as [n]. Second, we validate every citation against the actual retrieved evidence set; anything not in the set is caught. Third, on failure we retry once with a stricter prompt, and if citations are still invalid we strip them rather than publish them. And if there's no evidence at all, we don't even call the LLM — we return an honest insufficient-evidence message."

## 13. Knowledge Bites

- `GroundedGenerator.answer()` = classify → retrieve → pack → generate → validate.
- LLM sees only top-8 evidence — never the raw graph or query internals.
- `build_messages(strict=...)`: normal prompt, then stricter on retry.
- `validate_citations()` checks every `[n]` against retrieved evidence.
- Retry-then-strip: one strict retry, then remove bad citations.
- Four honest refusal paths: unsupported / no evidence / retrieval down / LLM down.
- Provider-agnostic via `LLMProvider` Protocol (Groq/OpenAI/Ollama/mock).
- Mock provider = illustrative only; UI labels it honestly.
